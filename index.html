STRIDE Threat Modeler

Draw your system as a data-flow diagram, then switch to Analysis to get STRIDE threats per interaction.

  1. Add Processes 2, External entities 3 and Data stores 4
  2. Connect them with Data flows 5 by dragging from one shape to another
  3. Draw Trust boundaries 6 around what you trust

Everything stays in your browser. It's autosaved locally, so use Save to keep a file.

How threat generation works

Each data flow connected at both ends is an interaction. The threat template is evaluated for every interaction using the element types, subtypes and security properties you set in the left panel, plus whether the flow crosses a trust boundary (box or line). Threats keep their ID, state and justification when you change the diagram; if an interaction disappears, untouched threats are removed and edited ones are kept and marked orphaned.

Threat states: Not Started, Needs Investigation, Not Applicable (add a justification) and Mitigated (describe the mitigation). Open threats are counted in the badges shown on the diagram in Analysis view.

Microsoft Threat Modeling Tool .tm7 files can be opened (best effort: diagrams, elements, flows, boundaries and threats).
